AI4ARTSED KNOWLEDGE BASE FOR TRASHY - COMPREHENSIVE USER GUIDE
Last updated: 2026-03-19

================================================================================
SECTION 1: PLATFORM OVERVIEW
================================================================================

AI4ArtsEd is a pedagogical-scientific experimentation platform for critical and creative engagement with generative AI in cultural education (ages 8-17). It is used in art-AI workshops with educators present.

CORE CONCEPT: The Large Language Model (LLM) acts as a co-actor in the creative process, not just a tool. It processes input based on its training data and creates something new. This is fascinating but also problematic - we don't know exactly how or why the model makes certain decisions.

KEY QUESTIONS WE EXPLORE:
- How do different models react to different inputs?
- What happens with detailed, nuanced descriptions instead of short prompts?
- How can we learn to truly understand what we want?
- How can we understand and change our image idea from many different perspectives?

SECTION 2: PLATFORM STRUCTURE
================================================================================

START PAGE (SELECT VIEW)
------------------------
Location: Route "/" (root)
Purpose: Users select RULES that will apply to their experiment.

CENTRAL ELEMENT: "Du bestimmst!" / "Your Call!"
- This is in the CENTER of the page
- It starts with an EMPTY rules box
- Users can write their own rules from scratch here

SURROUNDING ELEMENTS: Pre-made rule suggestions
- Everything around "Du bestimmst!" are INSPIRATIONS
- Users can select one to use as a starting point
- Or they can use these as examples to learn how rules work

The selected rules define:
- Creative constraints
- Style approaches
- Material specifications
- Perspective guidelines

IMPORTANT: The selected rules are automatically applied to all three modes - users don't need to re-enter them.

WHAT HAPPENS WITH THE RULES:
- A text AI will process the user's idea (WHAT) together with the rules (HOW)
- This creates an expanded, differentiated prompt
- The result can be:
  - Edited directly in the box
  - Regenerated by clicking "Start" again
  - Copied and pasted into the prompt box for further work

MODES AND PAGES
---------------

IMPORTANT: The selected RULES apply in the first THREE creative modes!
The difference between modes is WHAT you input (text vs images).
Canvas mode is different - you define the entire process yourself.
Workshop Planning and Developing Ideas are separate pages with their own purpose.

1. TEXT MODE (text_transformation.vue, route /pipeline-execution/:configId)
   Icon: "A" with arrow (translation symbol)
   Input: TEXT (your idea)
   How it works:
   - User enters an IDEA as text (WAS/WHAT should be created)
   - The text AI processes the idea together with the RULES
   - Creates an expanded prompt
   - User can observe, understand, and modify all intermediate steps
   - User selects output medium (image, video, audio, music)
   - User selects a generation model
   - Media is generated

2. IMAGE MODE (image_transformation.vue, route /image-transformation/:configId)
   Icon: Landscape/image symbol
   Input: ONE IMAGE (replaces the text prompt)
   How it works:
   - User uploads ONE image - this REPLACES the text prompt
   - User describes what should happen to it
   - The RULES still apply to the transformation
   - Vision model analyzes the uploaded image
   - Model creates a new version based on description + rules

3. MULTI-IMAGE MODE (multi_image_transformation.vue, route /multi-image-transformation)
   Icon: Grid with plus symbol
   Input: UP TO THREE IMAGES (replace the text prompt together)
   How it works:
   - User uploads UP TO THREE images - these REPLACE the text prompt
   - User describes how they should be combined
   - The RULES still apply to the combination
   - Vision-capable model (QWEN 2511) processes all images together
   - Creates fusion based on description + rules

4. CANVAS MODE (canvas_workflow.vue, route /canvas)
   Icon: Account tree / branching diagram
   Input: USER-DEFINED WORKFLOW (nodes connected by lines)
   How it works:
   - NO pre-selected rules apply - user defines the ENTIRE process
   - Visual node-based workflow builder
   - Drag-and-drop nodes, connect with lines
   - Define data flow from input through transformations to output
   - Supports parallel generation, evaluation, and recursive workflows
   - Designed for RESEARCH and SYSTEMATIC EXPLORATION

5. FLOW PAGE (x2x_flow.vue, route /x2x-flow)
   Icon: Waves (three stacked wave lines)
   Input: TEXT, IMAGE, OR SKETCH ON THE TABLE
   How it works:
   - Three nodes stand side by side. Creation is where material is added -
     text, image, or sketch - and it carries the four medium glyphs (image,
     video, sound, 3d) and shows the model that was resolved
   - Generation runs the transformation and reports it: the safety check,
     the progress, any error. Output shows the finished medium
   - Below the nodes lies a table that can be panned and zoomed, and
     material lies on it freely, wherever it is put
   - A circle zone sits on the table: if material lies in the zone, the next
     run reads only the zone, and an empty zone means the whole table is
     read
   - A glyph on the table opens the perspectives (the interception presets).
     A perspective placed in the zone is applied to what is read, several of
     them in the order they were laid in
   - Medium and model are INFERRED from the material, not chosen. A choice
     made by hand overrides the inference and is held
   - A third sign on the table, a pliable net over a rigid grid, opens the
     LoRAs: adapters trained over an image model from a series of images,
     which shift that model's output towards those images as soon as their
     trigger word stands in the prompt. The chooser lists what the register
     releases to this session, in up to three groups: the platform's, the
     course's, and the account's own trainings; with nothing released it says
     so ("no LoRA released to this session")
   - A chosen LoRA lies on the table as a tile. Lying in the zone, it is
     loaded with the next run that makes a picture, under the model that
     carries it: the automatic picks that model (Stable Diffusion 3.5 Large
     for every LoRA in the register today), the preparation node shows the
     net beside the model, the server puts the trigger word in front of the
     prompt where the prompt does not carry it yet, and the back of the
     finished card names the adapter and its strength under "LoRA"
   - A hold on the tile opens its strength: 50 to 100 percent of the trained
     strength, preset 80, with the trigger and the carrying models beside it;
     the x removes the tile
   - A model picked by hand holds. A LoRA that model cannot load, and a run
     that makes no picture, leave the tile where it lies with the "?" of
     unused material ("not used for this generation"); nothing becomes
     unselectable
   - The perspective "Cooked Film" brings its own adapter and wears the net on
     its bubble; under a model that does not carry it, the same "?"
   - Which LoRAs are offered stands in the LoRA register (Settings > LoRAs,
     admin): file, name, trigger, carrying models, release to platform, to a
     course, or to nobody. A training from the LoRA Training page is
     registered there before it is offered anywhere
   - Sound is one branch of the four. Song lyrics and a description of the
     style - genre, mood, instruments, timbre - are two texts that declare
     their own relation and route to HeartMuLa on their own; the model can
     also be picked by hand from the sound branch. Stable Audio 3 (sound,
     noise, ambience) and ACE Instrumental sit beside it in the same branch.
     Multiple languages are supported
   The three dedicated music pages (/music-generation, -simple, -advanced)
   were removed on 2026-08-05 and this is where writing a song moved to.
   The capability was not removed anywhere else either: Canvas has
   heartmula_standard as a node, and Developing Ideas can drive it directly with
   [GENERATE: heartmula_standard | lyrics || tags].

6. RE-ENACTMENT (cover_band.vue, route /cover-band)
   Icon: Music note
   Input: A MICROPHONE RECORDING (up to four minutes; the song comes back
   exactly as long as the recording was, and at least ten seconds)
   Stands NEXT TO music mode (5), it does not replace it: writing a song
   from lyrics and tags moved to the flow page, this is the re-enactment.
   How it works:
   - The group sings, hums, or holds a phone up and plays something
   - Machines pass the recording along in view, each station readable and
     named rather than numbered: the recording, sorted against a list of labels
     the platform wrote in advance, turned into words, written up as a song by
     a language model, sung back by HeartMuLa
   - The recording, the run and the song sit in a band across the top of the
     page. While the chain runs, the middle box opens over all three and
     reports it station by station — which machine, and how long it took. Each
     station that can be READ leaves that box as it answers and lands in the
     column below, and stays there to compare against once the song is playing
   - The page states NOTHING for itself: no title, no introduction, and not
     the terms either. Everything is said here instead, by this assistant, when
     somebody asks — including the terms, which is what a visitor asks first:
     a recording may run up to four minutes, the song comes back exactly as
     long as the recording was and at least ten seconds, and nothing is kept
   - The recording itself reaches only the first two stations: the sorting,
     where TWO models rank it against the list (CLAP-Music&Speech and
     MuQ-MuLan, both named on the page), and the transcription
     (HeartTranscriptor, also named). The model that writes the lyrics and
     HeartMuLa, which sings them, only ever get words. That is the whole
     point — the cover is built from a description
   - NO station is corrected or gated: point the microphone at an empty room
     and the transcriber still returns a confident sentence and the chain still
     runs. That is the demonstration, not a bug, and the page invites it
   - Nothing is kept: the recording is deleted the moment the stations are done
     with it; the song is served inline, is not a run, has no media-store
     entry, and cannot be favourited, exported or downloaded
   Pedagogically: original and re-enactment. What can an AI
   hear, what can it understand of music, and what does it sound like when it
   rebuilds that? The visitor is the original and the machine is the
   re-enactment — NOT the copy: a copy would be derivative and lesser, and this
   is productive, it brings something new. What it brings is to be looked at
   analytically, as bias, never morally as a bad likeness; HeartMuLa is the last
   of the four and performs the song from a description alone.
   The name is the term from performance studies, and it is earned by how the
   page is built, not claimed: a re-enactment is a repetition that shows itself
   AS one — framed, citing, with the difference to the original visible. Here
   every station stands on its own with the machine that made it named, the
   written words lie readable beside the song while it plays, the chain is
   visible as a chain, and nothing can be kept, so none of it can pass as the
   thing itself. That is what separates it from a child imitating a father,
   where the mimesis is unmarked and goes up in the doing.
   Worth suggesting when asked: record more than once, with music from
   different traditions and on different instruments, and compare what the
   sorting station claims to have heard each time. That station carries a
   measured finding on exactly this (Cross-Cultural Music Similarity, TISMIR 2025): across recordings from
   Western, Mediterranean, Middle Eastern, Indian and Chinese traditions, people
   separated the traditions about one and a half times as sharply as the best of
   seven audio models did. Also worth suggesting: point the microphone at an
   empty room and record nothing at all.
   Called Cover Band until 2026-08-10 and Silly Parrot until 2026-08-08; a group
   may still have an old name written down. The route is unchanged. In German
   the place is called "Nachspielen", not "Reenactment": the German loanword is
   a specialist term, while "ein Stück nachspielen" is the ordinary phrase for
   playing again what somebody else made, and it carries the as-if in the word.

7. COMPARE HUB (compare_hub.vue, route /compare)
   Icon: Compare arrows (two opposing arrows)
   Input: TEXT PROMPT or TEXT MESSAGE (depending on tab)
   How it works:
   - A hub of comparison tabs, each isolating ONE variable to reveal how AI works
   - Tabs have icons: image icon (photo) for image tabs, document icon for text tabs
   - KeepAlive: switching tabs preserves all state (chat history, inputs, results)

   IMAGE TABS:

   Tab 1: MODEL BIAS (image)
   - Same prompt to different image generation models (SD 1.5, SDXL, SD 3.5, Flux 2, Gemini)
   - Two presets: "Current top models" or "SD History" (evolution from 2022-2024)
   - Same seed, but each model has its own latent space → different results
   - Pedagogy: probes 12 bias dimensions — gender & gender roles, age, disability & body norms, phenotype & skin tone, ethnicity & cultural origin, socioeconomic status, body size & weight, beauty standards, sexual orientation & family forms, Global North default, religious & cultural symbolism, professional roles & occupations

   Tab 2: CULTURE BIAS (image)
   - Same image prompt in multiple languages → same model, same seed
   - Reveals how training data bias makes the AI "see" differently in different languages
   - CLIP/T5 text encoders trained ~80% on English → non-English prompts often produce defaults
   - Generates images side-by-side with VLM analysis of differences

   Tab 3: IMAGE UNDERSTANDING (image)
   - Upload or sketch an image, pick an analysis perspective (neutral, art-historical, ethical, decolonial, etc.)
   - Multiple vision models describe what they see → reveals what each model notices and misses
   - Perspectives include Panofsky (art-historical), Imdahl (iconic), Joerissen/Marotzki (educational theory)

   TEXT TABS:

   Tab 4: MODEL BIAS (text/LLM)
   - Same message to 3 different LLM models simultaneously
   - Each column has its own model selector + shared system prompt (selectable preset or custom)
   - Reveals how different training data, safety policies, and cultural perspectives produce different answers

9. LATENT LAB (latent_lab.vue, route /latent-lab)
   Icon: Flask / chemistry symbol
   Input: DEPENDS ON THE INSTRUMENT
   How it works:
   - Three labs behind one button, chosen by a tab: Image Lab, Latent Text Lab,
     Crossmodal Lab. The chosen lab and the chosen instrument are remembered
     across visits
   - IMAGE LAB — eight instruments, sorted by where they intervene: Denoising
     Archaeology and Attention Cartography change nothing and only look;
     Dimension Explorer, Concept Algebra and Encoder Fusion change the embedding
     once, before the denoising loop starts; the Encoder Fusion Workbench
     sweeps the fusion parameters across three axes; Composable Diffusion
     leaves every embedding untouched and instead combines what the model
     returns at each single step; Mean Images leaves the model alone as well
     and averages many finished pictures into one
   - LATENT TEXT LAB — Representation Engineering (find a concept direction in
     an LLM's activations and steer generation along it), Model Comparison (two
     LLMs layer by layer), Bias Archaeology
   - CROSSMODAL LAB — Latent Audio Synth (manipulate Stable Audio's T5
     conditioning space), MMAudio (image and text enter one network as separate
     signals), ImageBind Guidance (gradient steering during denoising)
   - Attention Cartography and Dimension Explorer need a large card. Below the
     VRAM threshold their tiles are switched off and say so, and name the
     environment variable that overrides the gate
   - The instruments have no addresses of their own here: which tile is open is
     remembered in the browser, so no link opens one directly

12. ENCODER FUSION AS A FLOW (surrealizer_flow.vue, route /surrealizer-flow)
    Entry: only by typing the route; the Image Lab's tile opens the complete
      form instead: ENCODER FUSION at /surrealizer
    Input: TEXT + SLIDER
    How it works:
    - Two readings of the same text meet. The CLIP encoders read language
      through images (CLIP-L 768d + CLIP-G 1280d, 77 tokens); T5-XXL reads it
      purely linguistically (up to 512 tokens, 4096d)
    - Drawn as a flow: the prompt, the three readers, the fusion showing its α,
      the generation, the image. Clicking a node opens it, clicking beside it
      closes it; while a run works, the generating node shows its progress
    - The slider (α) weights between the two readings, and the Fusion Strategy
      decides where the weighting acts - only the first 77 token positions
      carry both readings, everything past 77 is T5 alone
    - This form is not finished and is not the one to work in: only the
      prompt, the α slider and the fusion strategy can be set here. The
      negative prompt ("watermark"), CFG (5.5) and the T5 expansion (off) are
      fixed in the code, every run takes a fresh random seed, and a result
      cannot be kept from here. The complete form is ENCODER FUSION at
      /surrealizer, which the Image Lab's tile opens
    - Pedagogically: not a style filter. It shows that a model holds more than
      one reading of the same sentence, and that the readings can be pulled
      apart

13. ENCODER FUSION (surrealizer.vue, route /surrealizer)
    Entry: the Image Lab's "Encoder Fusion" tile, and its own route
    Input: TEXT + SLIDER
    How it works:
    - The instrument itself, complete: α, fusion strategy, negative prompt,
      CFG, seed and the T5 expansion are all on the page, and a result can be
      kept. ENCODER FUSION AS A FLOW at /surrealizer-flow is the same
      instrument drawn as a flow, and unfinished
    - A short prompt can be narratively expanded for T5 first, so the tail past
      77 tokens is text instead of padding
    - The negative prompt is extrapolated with the same α. It decides what the
      image extrapolates AWAY from, and different negatives give fundamentally
      different aesthetics

16. ATTENTION CARTOGRAPHY (attention_cartography.vue, Image Lab tile)
    Entry: the Image Lab's second tile - "See where the model looks"
    Input: TEXT
    How it works:
    - Generates an image and records at the same time which word influenced
      which region. Clicking a word lays its heatmap over the image; several
      words at once get different colours
    - Attention is not one word per region: influence is distributed across the
      scene, because the model reads the scene as a whole
    - Needs a large card and is switched off below the VRAM threshold
    - SECTION 6 carries the technical detail and the questions users ask

17. DIMENSION EXPLORER (feature_probing.vue, Image Lab tile)
    Entry: the Image Lab's fourth tile - "Dimension-level analysis"
    Input: TWO TEXTS
    How it works:
    - Compares two prompts and shows which dimensions of the embedding carry
      the difference between them, as a bar chart of the largest ones
    - Single dimensions can then be carried over from B into A; the page shows
      three images side by side on the same seed: A, A with the dimensions
      from B, and B
    - Which encoder is probed is a choice: CLIP-L (768d), CLIP-G (1280d) or
      T5-XXL (4096d)
    - Needs a large card and is switched off below the VRAM threshold
    - SECTION 6 carries the technical detail and the questions users ask

18. CONCEPT ALGEBRA (concept_algebra.vue, Image Lab tile)
    Entry: the Image Lab's fifth tile - "Vector arithmetic"
    Input: THREE TEXTS
    How it works:
    - Arithmetic on whole prompt embeddings: Result = A - Scale1 x B + Scale2 x C,
      after the word2vec analogies (King - Man + Woman), applied to images
    - Two sliders set how hard the subtraction and the addition pull (0-3); an
      L2 distance says how far the result moved from A
    - It happens in embedding space BEFORE generation, not during it - which is
      what separates it from a negative prompt
    - SECTION 6 carries the difference from negative prompts and the questions
      users ask

19. COMPOSABLE DIFFUSION (composable_diffusion.vue, Image Lab tile)
    Entry: the Image Lab's sixth tile - "Each concept scored separately"
    Input: SEVERAL TEXTS WITH WEIGHTS
    How it works:
    - Instead of one prompt as one vector, each concept gets its own pass
      through the transformer at every denoising step, and each adds its own
      pull on the image
    - Every concept carries a weight. A negative weight subtracts instead of
      adding, and the concept is marked as such
    - The one instrument in the Image Lab that leaves every embedding untouched
      and intervenes in the loop instead

20. ENCODER FUSION WORKBENCH (fusion_workbench.vue, Image Lab tile)
    Entry: the Image Lab's seventh tile - "3-axis comparison"
    Input: TEXT + THREE AXES
    How it works:
    - A comparison instrument, not a generator: pick which of the parameters
      varies along each of three axes and the runs are laid out against each
      other
    - What can vary: the prompt, the fusion weight (alpha), CFG, the seed, the
      fusion strategy (legacy, dual_alpha, normalized, centered_fade), and two
      band selections - which phase of the denoising and which depth band of
      the network the fusion acts in
    - It varies the Encoder Fusion parameters, which is where the name comes
      from; the instrument itself sits on the tile beside it

21. MEAN IMAGES (mean_images.vue, Image Lab tile)
    Entry: the Image Lab tile "Mean Images"
    Input: TEXT
    How it works:
    - Many pictures are generated and averaged into one mean image per cell.
      For the two SD 3.5 rows the mean is taken before the decoder: the
      latents of the pictures are averaged and decoded once. The other rows
      are averaged pixel by pixel, and each row says which mean it shows. A
      cell is one model in one column. "Reference" is the single picture from
      the prompt as entered. "Seed fixed" (its subtitle: prompt variants)
      holds pictures made from English rewordings of the prompt, which a
      language model writes, all on one seed. "Prompt fixed" (subtitle:
      random seeds) holds pictures made from the prompt as entered, each on a
      different seed
    - Set size 2 to 50 pictures per cell, on a slider. Models in rows, fastest
      first: SD 3.5 Large Turbo, CommonCanvas XL C, SD 3.5 Large, Flux 2
    - Three views of every cell: the mean, a relief (the mean of the pictures'
      fine detail: the texture the set shares, at a scale the mean itself
      blurs) and a contact sheet of the single pictures
    - What the fixed quantity dictates remains in the mean, what the varying
      one moves washes out
    - Named after Hito Steyerl's "Mean Images" (in: Medium Hot, Verso 2025):
      she calls the pictures an AI model generates mean images, "a rendition
      of correlated averages", an image made from statistical averages; the
      instrument's own note carries her sentences
    - Every finished set cell is listed under MEDIA ON THIS SURFACE as one
      run; view_run opens it and describes the mean, and the relief and the
      sheet are stored in the same run. The reference picture is listed under
      the run of its own generation

SECTION 3: TEXT MODE - DETAILED WORKFLOW
================================================================================

STEP 1: INPUT FIELDS (Two side-by-side bubbles)

LEFT BUBBLE - "Deine Idee" (Your Idea)
- Label: "Deine Idee: Worum soll es gehen?" / "Your Idea: What should it be about?"
- Purpose: User describes the SUBJECT MATTER - WHAT should be created
- Always editable, no restrictions
- When filled: border changes from white (low opacity) to blue with blue background

RIGHT BUBBLE - "Regeln/Eigenschaften" (Rules/Properties)
- Label: "Bestimme Regeln, Material, Besonderheiten" / "Define rules, materials, specifics"
- Purpose: Contains the meta-prompt defining HOW it should be realized
- Initially loaded from selected configuration in user's language
- Always editable - user can modify or write completely new rules
- IMPORTANT: The goal is for users to learn to formulate their OWN rules

STEP 2: INTERCEPTION (Verarbeitung)

What happens:
- User clicks first START button (triple arrow)
- LLM (Language Model) processes BOTH inputs together
- Combines the IDEA with the RULES
- Creates an expanded, differentiated prompt

Result display:
- Label: "Idee + Regeln = Prompt"
- Shows the LLM's output in a green-tinted box
- FULLY EDITABLE - user can modify everything
- This is a SUGGESTION, not a final result

WHY INTERCEPTION EXISTS:
1. Awareness of rules and material - By explicitly formulating rules, users become aware of what decisions they're making
2. Learning to understand prompts - Same basic idea can produce completely different results with different rules
3. Critical exploration of AI - How do models react to detailed, expressive prompts? Where are their limits?

STEP 3: MEDIA AND MODEL SELECTION

The platform is MULTIMODAL - not just images, but also:
- Images (various models)
- Video (LTX Video, Wan 2.2)
- Audio/Sound (Stable Audio)
- Music/Instrumental (ACE Instrumental)

AVAILABLE IMAGE MODELS:
- Stable Diffusion 3.5 Large (sd35_large) - blue, local, has prompt adaptation
- FLUX.2 (flux2) - orange, local, NO prompt adaptation
- Gemini 3 Pro Image (gemini_3_pro_image) - blue, cloud (EU, DSGVO via Mammouth AI)
- QWEN (qwen) - purple, vision-capable, local

VIDEO MODELS:
- LTX Video - fast local video generation
- Wan 2.2 Video - high-quality 720p video (5B model)

AUDIO MODELS:
- ACE Instrumental - AI music generation for instrumentals
- Stable Audio 3 - audio generation (music and sound effects)

THE EXCITING PART: Users can try the SAME prompt with DIFFERENT models - within one medium or even across media. This teaches how differently models react to the same input.

STEP 4: PROMPT OPTIMIZATION (depends on the model)

Not all models need the same prompt style. Here's what happens:

STABLE DIFFUSION 3.5:
- NEEDS optimization
- Prompt is converted to "classic" prompt style (keywords, weightings, tags)
- This is a good opportunity to LEARN how traditional prompting works
- Users can see how a natural description becomes a technical prompt

FLUX.2, GEMINI, QWEN:
- DON'T NEED optimization
- These models have their own language understanding built-in
- They understand natural language directly
- The interception result goes directly to the model

VIDEO MODELS (LTX, Wan 2.2):
- Receive optimization for SCENIC descriptions
- Prompts are adapted for movement, timing, camera work

AUDIO MODELS (ACE, Stable Audio):
- Receive optimization for AUDITIVE descriptions
- Prompts are adapted for sound, rhythm, musical structure

P5.JS (Special case):
- This generates CODE, not images
- Optimization prepares the prompt for code generation
- Output is a p5.js sketch that runs in the browser

Display:
- Label: "Modell-Optimierter Prompt"
- Shows in orange-tinted box
- FULLY EDITABLE - the optimized prompt is just a suggestion
- Users can always modify it before generation

STEP 5: TRANSLATION TO ENGLISH

At the end, the prompt is translated to English (if not already).
WHY? Because generative AI models usually only understand English really well.
We want users to work in their own language - so the system handles translation.
This step is currently not visible but happens in the background.

STEP 6: GENERATION

User clicks second START button to generate media.
- Progress animation shows during generation
- Duration: typically 20 seconds to 2 minutes depending on model
- Result displays in output frame
- Images can be clicked for fullscreen view
- Videos/audio have playback controls

SECTION 3b: CANVAS MODE - DETAILED GUIDE

WHAT IS CANVAS?

Canvas is a visual node-based workflow builder for creating custom AI pipelines.
Unlike the other three modes where pre-selected RULES apply, in Canvas you define
the ENTIRE process yourself - from input through transformations to output.

WHO IS CANVAS FOR?

Canvas is designed for:
- Older children (12+): Structured exploration of AI behavior
- Educators: Professional development for understanding genAI
- Researchers: Systematic investigation of model behavior, bias, creativity
- Workshop leaders: Creating research datasets through bulk generation

CANVAS BASICS

Every Canvas workflow has:
- ONE Input node (where text goes in)
- ONE Collector node (where results are gathered)
- Any number of processing nodes in between
- Connections (lines) showing data flow

HOW TO USE CANVAS

STEP 1: Open Canvas
- Click the Canvas icon (branching diagram) in the navigation
- You see a grid workspace with a toolbar on the left

STEP 2: Add Nodes
- Click nodes in the toolbar to add them to the canvas
- Drag nodes to position them
- Click a node to select it and see its settings

STEP 3: Connect Nodes
- Click the output connector (right side) of a node
- Then click the input connector (left side) of another node
- A line appears showing the connection

STEP 4: Configure Nodes
- Select a node to see its settings on the right
- Each node type has different options (see below)

STEP 5: Execute
- Click the Execute button
- Watch the workflow run node by node
- Results appear in the Collector

AVAILABLE NODE TYPES

1. INPUT PROMPT (Blue)
   - Entry point for your text
   - Type your prompt here
   - Every workflow needs exactly one

2. RANDOM PROMPT (Pink)
   - LLM generates creative content for you
   - Presets: Scenic Description, Photo Prompt, Artform, Instruction, Language
   - Good for exploring unexpected ideas

3. INTERCEPTION (Purple)
   - Pedagogical transformation of text
   - Same presets as the other modes (Bauhaus, Renaissance, etc.)
   - OR write your own transformation rules
   - This is where creative rules are applied

4. TRANSLATION (Amber)
   - Translates text to another language

   - Can be chained for "telephone game" effects

5. MODEL ADAPTION (Teal)
   - Optimizes prompts for specific AI models

6. GENERATION (Green)
   - Creates the actual media (image, audio, video)
   - Select which AI model to use
   - Can have MULTIPLE generation nodes for comparison

7. EVALUATION (Amber)
   - LLM judges the output
   - Types: Fairness, Creativity, Bias, Quality, Custom
   - Can BRANCH the workflow based on results

8. PREVIEW (Green)
   - Shows intermediate results inline
   - Good for debugging and understanding

9. MEDIA OUTPUT / COLLECTOR (Cyan)
   - Collects ALL workflow outputs
   - Shows results with source attribution

SPECIAL CANVAS CAPABILITIES

PARALLEL GENERATION:
- Connect one Interception to MULTIPLE Generation nodes
- Compare how different models interpret the same prompt
- All results appear in the Collector

RECURSIVE WORKFLOWS:

SECTION 6: EXPERIMENTAL WORKFLOWS
================================================================================

These approaches work at a deeper technical level and make the "black box" somewhat visible:

SURREALIZER
-----------
Turns the model's CLIP reading of the prompt against itself while T5 keeps
holding the theme. Not a blend of two readings — there is no common frame to
blend in.
- Each encoder reads differently: CLIP visual-lexical (77 tokens, hard
  truncation), T5 linguistic-compositional (512 tokens). In the shared
  dimensions the two are orthogonal (cos = 0.03).
- Measured: past alpha > 1 the CLIP core flips anti-parallel (cos = -0.985).
  What gets inverted is the model's own literal reading, which is why the
  image stays related to the prompt: the theme with its habitual
  illustration withdrawn, not the opposite of the prompt.
- At high alpha, faces and figures appear that no one asked for — also for
  prompts with no people — and the process imprints its own vocabulary (red
  inversion, tube insertion, flattening). The priors show once the prompt
  stops masking them.
- Random shifts of the same magnitude barely change the image: almost every
  direction in conditioning space is a wall, this one is a door.
- The blackout beyond +/-75 is a number-format edge (fp16 overflow), not a
  limit of meaning. The UI limit sits at +/-75 for that reason.
Status: the mechanism is measured (encoder-side inversion measurement, 175+144
renders, plus a pre-registered series of 137). The Surrealizer as a whole is
drawn more sharply in concept than it is probed in fact.

THREE FUSION MODES:
- Dual Alpha (default): Structural anchor — the first 77 tokens (CLIP range)
  are influenced at only 15% of the α value, the rest at full α. The subject
  stays recognizable, surreality comes from the T5 tokens beyond position 77.
- Normalized: Uniform α across all positions, then L2-normalized to mean T5
  magnitude. Provides controlled intensity without the dual-zone behavior.
- Legacy: Original behavior — LERP on the first 77 tokens, rest appended
  unchanged. Can dilute surreal effects on long prompts because unmodified
  T5 tokens (positions 78+) overwhelm in MMDiT attention.

LATENT LAB — ATTENTION CARTOGRAPHY
-----------------------------------
Location: Route "/latent-lab" → Tab "Attention Cartography"

What it does:
- Generates an image from a prompt AND simultaneously records which word
  influenced which image region (cross-attention maps)
- Users click on words to see colored heatmap overlays on the generated image
- Multiple words can be selected simultaneously (different colors)

How it works technically:
- SD3.5's MMDiT transformer has 24 layers where text and image tokens attend
  to each other via "joint attention"
- We replace the default fast attention (SDPA) with a manual softmax(QK^T/√d)
  processor at 3 selected layers to extract the text→image attention submatrix
- Maps have 64×64 resolution (patch grid), upscaled to image resolution

Key concepts to explain to users:
- Attention is NOT "one word = one region". It distributes influence contextually.
  A "house" in a farm scene also influences the area around animals because the
  model understands the scene holistically.
- TWO INDEPENDENT axes: Denoising step (WHEN in the 25-step generation process)
  and Network depth (WHERE in the 24-layer transformer stack).
- Shallow layers capture global composition planning, middle layers semantic
  assignment, deep layers fine detail. ALL layers are active at EVERY step.
- Early denoising steps show rough layout, late steps show detail refinement.
- Subword tokenization: The CLIP-L encoder splits unknown words into subtokens
  (e.g., "Kugel" → "Ku"+"gel"). The UI automatically groups these back into
  whole words, but users can see the subtoken count in parentheses.
- The B/W mode desaturates the base image so heatmap colors stand out clearly.
  "Off" hides the base image entirely to show pure attention patterns.

Common questions users might ask:
- "Why does 'house' also light up at the animals?" → The model processes the
  entire scene context, not isolated words. Semantically related concepts
  (farmhouse + animals) share attention. Try deeper layers for more precise localization.
- "Why is the heatmap so blurry?" → Attention maps are 64×64 (patch resolution),
  not pixel-precise. This IS the actual resolution the model works at internally.
- "What's the difference between the step slider and the depth buttons?" →
  Step = when in the noise-to-image process. Depth = where in the neural network.
  They are completely independent — explore all combinations.
- "Why does the same word look different at different steps?" → Early steps
  plan rough layout (broad, diffuse attention), late steps refine details
  (more focused attention). The model's "attention strategy" changes over time.

LATENT LAB — DIMENSION EXPLORER
--------------------------------
Location: Route "/latent-lab" → Tab "Dimension Explorer"

What it does:
- Compares two prompts (A and B) to find which embedding dimensions encode
  the semantic difference between them
- Shows a bar chart of the top dimensions with the largest difference
- Users can selectively transfer specific dimensions from B into A
- Generates three images on the same seed, in this order: original A, modified
  A, original B. The second run makes original B first when there is none for
  the current prompt B, seed, steps, CFG and negative prompt, and otherwise only
  modified A. If original B is refused, modified A is not made either
- The first run measures on all four encoder choices at once; a change of
  encoder switches the list and starts no run
- This reveals what specific embedding dimensions "encode" visually

How it works technically:
- SD3.5 has three text encoders: CLIP-L (768d), CLIP-G (1280d), T5-XXL (4096d)
- Users choose which encoder to probe
- Both prompts are encoded, then the per-dimension absolute difference is
  computed (averaged across all token positions)
- For transfer: selected dimensions in prompt A's embedding are replaced with
  the corresponding values from prompt B's embedding
- Same seed ensures the only visual change comes from the embedding modification

Key concepts to explain to users:
- Embeddings are HIGH-DIMENSIONAL vectors (4096 dimensions for T5). Each
  dimension is not a named "feature" — meaning is distributed across many
  dimensions simultaneously.
- Changing one word (e.g., "red" → "blue") changes MANY dimensions, not just
  one. The bar chart shows which changed MOST, but even small changes in
  many dims can have cumulative effects.
- The threshold slider is a quick way to select "all dimensions above X
  difference". Lower threshold = more dimensions transferred = closer to
  fully replacing A with B.
- T5-XXL (4096d) typically shows the richest semantic encoding. CLIP-L (768d)
  is more compressed. CLIP-G (1280d) is in between.
- Not all high-difference dimensions produce visible image changes. Some
  dimensions encode subtleties that the DiT denoiser doesn't strongly respond to.

Common questions users might ask:
- "Why doesn't transferring the top dimension change anything?" → Meaning is
  distributed. Try transferring the top 10 or 20 dimensions together. Often
  a semantic concept is spread across a cluster of dimensions.
- "Why do different encoders show different results?" → Each encoder learned
  different representations. T5 is a language model (4096d, token-level
  context), CLIP models are vision-language aligned (768/1280d, global
  sentence embedding). They encode semantics differently.
- "What does dimension 2847 'mean'?" → Individual dimensions don't have fixed
  semantic meanings. They represent directions in a learned vector space.
  The same dimension might encode color in one context and texture in another.
- "Can I transfer dimensions from a completely different prompt?" → Yes! That's
  the experimental spirit. Try transferring "ocean" dimensions into a "desert"
  prompt and see what happens.

LATENT LAB — CONCEPT ALGEBRA
-----------------------------
Location: Route "/latent-lab" → Tab "Concept Algebra"

What it does:
- Vector arithmetic on prompt embeddings: A − B + C = ?
- Inspired by word2vec analogies (King − Man + Woman ≈ Queen), applied to
  entire prompt embeddings and image generation
- Three prompts are encoded, algebraically combined, and used to generate
- Scale sliders control intensity of subtraction and addition (0–3)
- L2 distance shows how far the result moved from the original

How it works technically:
- The formula: Result = A − Scale₁ × B + Scale₂ × C
- Operation happens in embedding space BEFORE image generation, not during
  the diffusion process — one arithmetic step on the conditioning vector
- Applied to the chosen encoder embeddings (CLIP-L 768d, CLIP-G 1280d,
  T5-XXL 4096d, or all combined) and pooled embeddings (2048d)

Key difference from negative prompts:
- Negative prompts steer the denoising process away from B at EVERY one of
  the 25 steps — the model decides step by step how to interpret "not B"
- Concept Algebra computes a new vector BEFORE generation: the subtraction
  happens in embedding space, not in the diffusion process
- Result: a different kind of intervention, not a more precise one. What this
  house measured at this locus: linear subtraction does NOT reliably remove
  the named thing from the image. Peripheral scene elements can drop out and
  the rest recomposes coherently; the core subject persists. Subtraction
  lowers the embedding's L2 norm monotonically, and past roughly 0.85-0.9
  (for a mean of several items) the image collapses rather than losing the
  concept. The semantic label of what is subtracted does not predict the
  visual effect in general.
- Two limits on those figures, stated plainly: they come from the research
  path (subtracting the mean of phrase embeddings), not from this tab's
  A - B + C, which has not been probed the same way; and the single-seed
  results are marked provisional in the report.
- The negative result is the pedagogical point, and it is not a glitch:
  nothing breaks, the model works correctly throughout. What shows is a
  trained necessity — and the collapse is the lawful answer to a demand that
  cannot be met.

Common questions users might ask:
- "Why is this different from a negative prompt?" → Fundamentally different
  mechanism. Negative prompts guide the noise-removal process step by step.
  Concept Algebra performs a one-time vector operation before generation begins.
- "Is the operation commutative?" → No. A − B + C ≠ A − C + B. The
  subtraction and addition happen relative to A's position in vector space.
- "Can I remove something from the image with this?" → Usually not, and that
  is the finding rather than a failure of the operation. See above.

LATENT LAB — DENOISING ARCHAEOLOGY
------------------------------------
Location: Route "/latent-lab" → Tab "Denoising Archaeology"

What it does:
- Makes every one of the 25 denoising steps visible as an image
- A filmstrip shows the complete creation process, a timeline slider allows
  browsing through the steps
- Reveals that diffusion models work everywhere simultaneously, from rough
  structures to fine details (not left-to-right like drawing)

Three phases visible in the filmstrip:
1. Early steps (1–8): Global composition — basic structure, color distribution,
   layout planning. The model "plans" the overall scene.
2. Middle steps (9–17): Semantic emergence — objects become recognizable,
   shapes crystallize. Individual concepts gain form.
3. Late steps (18–25): Detail refinement — textures, edges, fine patterns.
   The model polishes fine details.

How it works technically:
- SD3.5 uses Rectified Flow as scheduler with 25 default steps
- At each step, current latent vectors are decoded through the VAE (1024×1024)
- Latent representation: 128×128 at 16 channels — each latent pixel corresponds
  to an ~8×8 pixel patch in the image
- Even pure Gaussian noise becomes coherent color clusters because the VAE
  translates each latent position into a spatial patch

Common questions users might ask:
- "Why does the first step show colored blobs, not pixel noise?" → The noise
  lives in latent space (128×128), not pixel space. The VAE decoder translates
  each latent pixel into an 8×8 pixel patch, creating spatial coherence.
- "Why does the model seem to 'know' the layout so early?" → Early denoising
  steps set global structure because the noise schedule is designed that way —
  large-scale changes happen first, small-scale refinements last.

LATENT LAB — TEXT LAB
======================

Three research tools for investigating language models at the activation level.
Requires adult/research safety level. All tools run on the GPU service.

TEXT LAB — REPRESENTATION ENGINEERING
--------------------------------------
Location: Route "/latent-lab" → Tab "Text Lab" → "Representation Engineering"

What it does:
- Based on Zou et al. (2023) "Representation Engineering"
- LLMs encode abstract concepts (truth, sentiment, ethics) as directions in
  high-dimensional activation space
- Through contrast pairs (true vs. false sentence), the direction encoding a
  concept can be extracted
- Adding this direction at runtime changes model behavior — without retraining

How to use it:
1. Enter contrast pairs (e.g. "The capital of France is Paris" vs.
   "The capital of France is Berlin") — at least 3 pairs recommended
2. Click "Find direction" — PCA extracts the concept direction
3. Enter a test prompt (e.g. "The capital of Germany is")
4. Use the α slider to steer generation along the concept direction:
   - α = 0: baseline (correct answer)
   - α = -1: inverted direction (wrong answer, even though model "knows" right)
   - α = +1: reinforced direction (little change, already correct)
   - |α| > 2: artifacts dominate (repetitions, nonsense)

Key concepts to explain to users:
- "Explained variance" > 50% indicates clean concept separation
- The "sweet spot" per Zou et al. is |α| between 0.5 and 2.0
- Different transformer layers influence different aspects: early = syntax,
  late = semantics
- English prompts work significantly better (most open-source LLMs are
  primarily English-trained)

TEXT LAB — MODEL COMPARISON (CKA)
----------------------------------
Location: Route "/latent-lab" → Tab "Text Lab" → "Model Comparison"

What it does:
- Based on Belinkov (2022) "Probing Classifiers" and Olsson et al. (2022)
- Loads two language models and compares their internal representations
  layer by layer
- CKA (Centered Kernel Alignment) heatmap shows which layers represent
  information similarly
- Attention comparison shows where each model "looks" in the text
- Same-seed generation comparison shows behavioral differences

Key concepts to explain to users:
- Bright cells in the heatmap = high representational similarity
- Diagonal patterns = models process information in similar order
- Early layers (syntax) are often similar across models
- Late layers (semantics/world knowledge) diverge more strongly
- CKA is invariant to rotation and scaling — it measures structural
  similarity, not identical numbers

TEXT LAB — BIAS ARCHAEOLOGY
-----------------------------
Location: Route "/latent-lab" → Tab "Text Lab" → "Bias Archaeology"

What it does:
- Based on Zou et al. (2023) and Bricken et al. (2023) "Towards Monosemanticity"
- Systematic bias experiments through controlled token manipulation
- Four experiment types:
  1. Gender: Suppresses all gendered pronouns — which gender does the model
     choose as default?
  2. Sentiment: Boosts positive or negative words — how strongly does the
     entire text flow change?
  3. Domain: Boosts scientific or poetic vocabulary — observe register shifts
  4. Custom: Define your own boost/suppress token lists

How it works technically:
- Suppression: Token logits set to -∞ before sampling (can never be generated)
- Boosting: Token logits increased before sampling
- Multiple samples per condition enable statistical comparison
- Results show baseline vs. manipulated generations side by side

Key concepts to explain to users:
- The differences between baseline and manipulated generations reveal biases
  encoded in the training data, not intentional design choices
- Example: "The doctor said to the patient" with gender suppression reveals
  which gender the model defaults to for "doctor"
- Custom experiments let users test their own hypotheses about model biases

LATENT LAB — CROSSMODAL LAB
=============================

Three tools bridging image and audio generation through shared latent spaces.
Requires adult/research safety level.

CROSSMODAL LAB — LATENT AUDIO SYNTH
-------------------------------------
Location: Route "/latent-lab" → Tab "Crossmodal" → "Latent Audio Synth"

What it does:
- Direct manipulation of Stable Audio's T5 conditioning space (768d)
- Instead of changing WHAT the model generates (via prompt), change HOW
  the model internally understands the text
- Interpolate between two prompts, extrapolate beyond, scale embeddings,
  inject noise

Parameters:
- Alpha: 0 = Prompt A only, 1 = Prompt B only, 0.5 = blend, >1 = extrapolation
  beyond B, <0 = opposite direction from B
- Magnitude: Global embedding scaling (1.0 = unchanged, higher = more intense)
- Noise: Gaussian noise injection for unpredictable variations
- Spectral Strip: Shows all 768 dimensions as bars — drag to shift individual
  dimensions, directly manipulating the sound. Right-click resets.

Synthesis tools:
- Looper/Sequencer: Create rhythmic patterns from generated audio clips
- Wavetable mode: Morph between audio frames using a scan position
- MIDI control: Play the generated sound as an instrument via MIDI keyboard
- ADSR envelope: Shape note dynamics (Attack/Decay/Sustain/Release)
- Arpeggiator: Automatic note patterns (up, down, up-down, random)
- Semantic Axes: Steer embedding in specific directions using text pole pairs

Common questions users might ask:
- "Why do two similar prompts sound very different?" → T5 embedding space
  encodes semantic relationships, not acoustic similarity. "Ocean waves" and
  "sea sounds" might be far apart in 768d space despite sounding related.
- "What does the magnitude slider do?" → It scales the entire embedding vector.
  Think of it as "volume" in meaning-space — higher values produce more
  confident, intense interpretations.

CROSSMODAL LAB — MMAUDIO
--------------------------
Location: Route "/latent-lab" → Tab "Crossmodal" → "MMAudio"

What it does:
- Image and text enter the same network as separate signals — the image is
  NOT translated into language first
- The model was jointly trained on video and audio (CVPR 2025)
- Learned direct associations: forest → birdsong, street → traffic, guitar → plucking
- Up to 8 seconds, 44.1kHz, ~1.2s compute time

Parameters:
- Image upload (optional): The visual target for audio generation
- Text prompt (optional): Additional or sole steering signal
- Negative prompt: Sounds you do NOT want (e.g. "speech, music")
- Duration: 1–8 seconds
- CFG Strength: 2–3 = varied results, 6–8 = more prompt-faithful

Key concepts to explain to users:
- Using both image AND text produces richer results than either alone
- The model processes image features directly, not via CLIP text translation
- Try comparing: same text with vs. without an image — the difference shows
  what the visual signal contributes

CROSSMODAL LAB — IMAGEBIND GUIDANCE
-------------------------------------
Location: Route "/latent-lab" → Tab "Crossmodal" → "ImageBind Guidance"

What it does:
- Gradient-based steering during Stable Audio's denoising process
- ImageBind (Girdhar et al., CVPR 2023) provides a shared 1024d embedding
  space for image and audio (plus text, depth, heat, motion)
- At each denoising step, the system asks "Does this sound like the image?"
  and corrects the direction via cosine similarity gradient

Parameters:
- Image upload: Target direction for the sound
- Base prompt (optional): Additional text steering
- λ Guidance Strength: 0.01–0.05 = lots of freedom, 0.3–1.0 = closely tied
  to image
- Warmup Steps: From which step guidance kicks in — low = immediate, higher =
  basic structure forms unguided first
- Total Steps and Duration: Control quality and length

Key difference from MMAudio:
- MMAudio: Jointly trained network, image is a native input channel
- ImageBind Guidance: External steering via a separate multimodal embedding
  space — conceptually related to Classifier Guidance (Dhariwal & Nichol, 2021)
- Result includes cosine similarity showing how close the sound came to the image

SECTION 8: SAFETY LEVELS AND CONTENT PROTECTION
================================================================================

Four safety levels exist:
- KIDS (Kinder): Most restricted, appropriate for ages 6-12
- YOUTH (Jugend): Default level, appropriate for ages 13-17
- ADULT (Erwachsene): Minimal filtering (18+), only illegal content blocked (§86a StGB)

The safety level is set by the supervising educator, not by students.
It determines what content can be generated.

SAFETY IS NOT ONE THING - IT HAS DIFFERENT MEANINGS AT DIFFERENT STAGES:

1. §86a StGB Compliance (Stage 1 - always active):
   - Blocks Nazi symbols, terrorist organization symbols, extremist codes
   - Required by German law, applies at ALL safety levels (even "adult")
   - Uses fast keyword filter + LLM verification

2. DSGVO/Privacy Protection (Stage 1 - always active):
   - Detects personal data (names, addresses) via SpaCy NER
   - Prevents personal data from reaching image generators
   - Legal requirement, applies at ALL safety levels

3. Age-Appropriate Content (Jugendschutz) (Stage 1 + Stage 3):
   - Checks if prompts contain age-inappropriate content
   - Different thresholds for kids vs youth
   - Skipped for "adult" and "off" levels

4. Post-Generation Image Safety (VLM check - after Stage 4):
   - NEW: A Vision-Language Model (qwen3-vl:2b) analyzes the GENERATED IMAGE
   - Text-based checks cannot predict what an image generator actually produces
   - A harmless prompt can produce a disturbing image
   - The VLM looks at the actual image and decides: "safe" or "unsafe"
   - Only runs for images (not code/audio/video) at kids/youth levels
   - If the VLM flags the image as unsafe, it is blocked before reaching the user
   - If the VLM service is unavailable, the image passes through (fail-open)

WHY MULTIPLE LAYERS?
- Stage 1+3 catch bad PROMPTS before wasting generation time
- VLM catches bad IMAGES that slipped through text checks
- §86a and DSGVO are LEGAL requirements, always active
- Jugendschutz is PEDAGOGICAL, adjustable per safety level

Q: How long does generation take?
A: Depends on model and complexity. Usually 20 seconds to 2 minutes. Progress is shown during generation.

Q: Can I edit the AI's suggestions?
A: YES! Everything is editable - the interception result, the optimized prompt, even the rules. The AI provides suggestions, but YOU have full control.

A: Ask this chat for help, or ask the course instructor who is present. It's completely okay not to know everything.

Q: Can I use my own images?
A: Yes, in Image Mode (one image) or Multi-Image Mode (up to three images). You can also use images you generated on the platform.

Q: What is Canvas and when should I use it?
A: Canvas is a visual workflow builder where you connect nodes to create custom AI pipelines. Use Canvas when you want to: explore how different transformations affect results, compare multiple AI models side-by-side, create evaluation loops for quality control, or do systematic research on AI behavior. It's more advanced than the other modes but gives you complete control.

Q: What's the difference between Canvas and the other modes?
A: In Text/Image/Multi-Image modes, you select rules that apply automatically to your input. In Canvas, NO pre-selected rules apply - you build the entire process yourself using nodes. You decide what transformations happen, in what order, and can even create feedback loops.

Q: How do I start with Canvas?
A: Start simple! Create: Input → Interception → Generation → Collector. That's the basic pattern. Then add complexity: try parallel generations to compare models, add Preview nodes to see intermediate results, or experiment with Evaluation for quality control.

Q: What are evaluation nodes good for in Canvas?
A: Evaluation nodes let an LLM judge the output based on criteria you define (fairness, creativity, bias, quality, or custom). With branching enabled, you can create FEEDBACK LOOPS: if evaluation fails, the workflow can iterate and try again. This is powerful for bias exploration and systematic research.

Q: Can I create multiple images at once in Canvas?
A: Yes! Connect one node to MULTIPLE Generation nodes (fan-out). All results appear in the Collector. This is great for comparing how different AI models interpret the same prompt.

SECTION 15: STAGE2 PROMPT QUALITY CRITERIA
================================================================================

The configurations (rules) that users select are called "Stage2 Interception Prompts".
They determine HOW user input is transformed. This section explains what tends to make
transformation prompts work well and can help explain to users why certain rules work better.

NOTE: These are guidelines for orientation, not rigid rules. Practical workshop experience
matters more than structural completeness. Use this as a thinking framework, not a checklist.

THE WAS/WIE PRINCIPLE
---------------------
- WAS (WHAT): The user's input - the core idea
- WIE (HOW): The config.context - the transformation rules

The LLM acts as a "Co-Akteur" (co-actor), not just a tool:
- It interprets user input according to explicit rules
- Applies the transformation framework consistently
- Adds its own "handwriting" through interpretive choices
- Results are collaborative, not mechanical

Stage2 prompts are NOT about making "better" prompts.
Stage2 prompts ARE about:
- Making visible HOW rules transform ideas
- Making editable - users can intervene at every step
- Making comparable - different rules on same idea
- Making criticalizable - students discuss transformation choices

THE 3-PART TEMPLATE STRUCTURE
-----------------------------
All Stage2 prompts work within this structure:

Task:        Generic instruction (HOW to transform)
Context:     Specific rules from the config
Important:   Respond in the same language as the input prompt below.
Prompt:      User's original text

QUALITY CRITERIA FOR TRANSFORMATION RULES
-----------------------------------------

1. PERSPECTIVE-TAKING OVER IMITATION
   GOOD: "DU BIST eine Künstlerin der 1870er Jahre. Du lebst in..."
   BAD:  "Generate in vintage style"
   FORBIDDEN: "in the style of [artist name]"

2. CLEAR METHODOLOGY WITH STEPS
   GOOD: "1. Analysiere... 2. Wende an... 3. Reduziere... 4. Beschreibe..."
   BAD:  "Be creative and make something beautiful"

3. SPECIFIC PROHIBITIONS
   GOOD: "FORBIDDEN: romanticizing terms ('nostalgic glow'), digital terminology"
   BAD:  "Don't be too kitschy"

4. OUTPUT FORMAT SPECIFICATION
   GOOD: "One paragraph, 120-180 words"
   BAD:  No length hint at all

5. META-COMMENTARY PROHIBITION
   GOOD: "NO meta-commentary ('I will...', 'This shows...')"
   Missing this causes LLM to explain instead of transform

RED FLAGS (require immediate revision)
--------------------------------------
- Placeholder text ("professional translator", "prompting expert")
- Artist name as style reference ("in the style of Monet")
- Empty context fields
- No prohibition of meta-commentary
- Optimization framing ("make better", "improve")

QUALITY LEVELS (rough orientation)
-----------------------------------
Excellent: Complete methodology, examples, prohibitions, output format
Good: Functional with minor improvements possible
Weak: Missing key elements, unclear transformation
Problematic: Placeholder text, no guidance, or poor practical results

GOLD STANDARD EXAMPLES
----------------------

PHOTOGRAPHY (analog_photography_1870s):
- Role identity: "Du bist eine professionelle Fotografin..."
- Material constraints: "silver-iodized copper plates, mercury development"
- Prohibitions: "FORBIDDEN: romanticizing terms, 'in the style of [photographer]'"
- Format: "One paragraph, 120-180 words"

ART HISTORY (bauhaus):
- 4-step methodology: Analysis → Functionalism → Geometric Reduction → Material/Color
- Perspective prohibition: "ES IST DIR VERBOTEN... 'Im Stil von'"
- Transformation examples: "Vase → functional prototype for cylindrical container"

CRITICAL THINKING (planetarizer):
- Clear framework: Anthropocene thinking, planetary perspective
- Strict prohibitions: "Othering, exoticization STRICTLY forbidden"
- Named theoretical basis: "Frantz Fanon, Homi Bhabha, Gayatri Spivak"

SPECIAL CASES
-------------

PASSTHROUGH CONFIGS (skip Stage2):
- Surrealizer
- It has a minimal/empty context BY DESIGN
- It passes the prompt directly to a specialized ComfyUI workflow

USER-DEFINED CONFIG:
- "Du bestimmst!" has empty context BY DESIGN
- User provides their own rules via UI

LORA-TRIGGER CONFIGS (e.g., Cooked Negatives):
- Must include trigger term instruction to activate the LORA
- Can be brief if LORA handles the aesthetic

WHY THIS MATTERS FOR USERS
--------------------------
When users ask about why certain configurations work better:
- Good configs ADOPT A PERSPECTIVE, not just surface style
- Good configs have CLEAR STEPS the LLM can follow
- Good configs PROHIBIT common failure modes explicitly
- Good configs specify OUTPUT FORMAT so results are usable

When users want to write their own rules:
- Start with role identity: "Du bist..."
- Add numbered steps or phases
- Include specific prohibitions for what NOT to do
- Specify output length and format
- Ensure the rules work for ANY input (WAS), not just specific content

CORE IDEA
---------
Every AI generation consumes real energy and produces real CO2. The animations turn
this abstract fact into something students can see, feel, and interact with. The
platform reads real GPU power data (watts, temperature) and uses it to drive the
animations — so they reflect actual resource consumption, not made-up numbers.

THE THREE ACTIVE ANIMATIONS (randomly selected per generation)
--------------------------------------------------------------

1. FOREST MINI-GAME ("Bäume pflanzen")
   - Students click to plant trees while waiting
   - Factories automatically spawn and destroy trees — representing the pollution
     caused by the GPU powering their generation
   - Real-time stats: GPU power, tree count, total CO2 produced
   - Key learning: A single tree absorbs about 2.5g CO2 per hour. The animation
     shows how many minutes a tree would need to offset this one generation
   - Pedagogical message: Even a single image has a measurable carbon footprint

2. ICEBERG ANIMATION ("Arktisches Eis")
   - Students draw icebergs on a canvas
   - The icebergs melt proportionally to the GPU energy consumption
   - Physics simulation: icebergs float, rotate, and shrink realistically
   - Water temperature rises with accumulated CO2
   - Key learning: CO2 emissions have a direct (if tiny) effect on polar ice.
     The animation visualizes this relationship in an exaggerated but proportional way
   - Pedagogical message: Computing is physical — it happens on real hardware that
     produces real heat and real emissions

3. GPU STATS ANIMATION ("Was passiert gerade?")
   - Shows an animated sprite of the GPU "working hard"
   - Real-time power gauge, temperature, energy consumption
   - Comparison metric: "This generation used as much energy as X minutes of
     smartphone use"
   - Rising bubbles with AI facts
   - Pedagogical message: Demystifies what happens "under the hood" — AI generation
     is not magic, it is massive computation on specialized hardware

PLANNED (currently disabled): RARE EARTH MINI-GAME
   - Would visualize the mining of rare earth elements (Neodymium, Dysprosium,
     Terbium) needed to build GPUs
   - Conveyor belt transports minerals while sludge pollutes a lake
   - Students click to clean up pollution
   - Topic: The hidden supply chain behind the hardware

HOW TO TALK ABOUT THIS WITH STUDENTS
-------------------------------------
- The animations are designed to spark discussion, not to guilt-trip anyone
- "Did you notice the factory in the forest game? What do you think it represents?"
- "How many trees would we need to plant to offset a whole class doing AI art?"
- "Is it worth it? When is AI generation worthwhile, and when might simpler tools
  be better?"
- The point is AWARENESS, not prohibition. We use AI — but we should understand
  what it costs

TECHNICAL DETAILS (if students ask)
------------------------------------
- The platform reads real GPU stats via nvidia-smi every 2 seconds
- CO2 is calculated using the German electricity grid average (~400g CO2/kWh)
- Energy formula: GPU watts / 3600 = watt-hours per second of generation
- All comparison metrics (trees, smartphones, ice) use published scientific data
- If no GPU data is available, the animation uses realistic simulated values

SECTION 17: WHY SOME RULES WORK BETTER THAN OTHERS (PROMPT COLLAPSE)
================================================================================

Sometimes a rule configuration produces results that all feel the same - like the
AI got stuck in one mood or one way of thinking. This is called "collapse" and it
happens because of how the AI was trained. Here's how to recognize it and fix it.

WHAT IS COLLAPSE?
-----------------
Collapse means the AI locks onto ONE way of interpreting your rules and ignores
everything else. For example:
- You write rules that say "show BOTH the beauty of nature AND social problems"
- But the AI only shows social problems. The beauty disappears.
- Every result feels sad and heavy, no matter what you type as input.

This is NOT your fault. It's a pattern in how AIs learn from their training data.

WHY DOES COLLAPSE HAPPEN?
--------------------------
1. THE AI PREFERS "TYPICAL" RESPONSES
   When the AI sees the word "critical" or "ecological," it remembers millions of
   texts about problems, suffering, and catastrophe. So it produces more of that.
   It's like asking someone to think about "the ocean" — most people think of
   beaches, not deep-sea trenches. The AI has similar habits.

2. THE AI CAN'T DO "NOT"
   If your rules say "NOT a dystopia," the AI often ignores the "NOT" and just
   sees "dystopia" — and then produces exactly that! This is a known problem with
   all current AI language models. It's like telling someone: "Don't think about
   a pink elephant." What do you think of? Exactly.

3. ONE STRONG DIMENSION SWALLOWS EVERYTHING ELSE
   If your rules mention ecology, environment, sustainability — the AI will make
   EVERYTHING about environmental damage. Even a birthday party becomes a lecture
   about plastic waste. The "ecological" dimension swallows all other dimensions.

HOW TO WRITE COLLAPSE-RESISTANT RULES
--------------------------------------

TRICK 1: SAY WHAT YOU WANT, NOT WHAT YOU DON'T WANT
   BAD:  "This should NOT be dystopian"
   GOOD: "Describe soberly, densely, and concretely. Only description."

   Instead of saying what to avoid, describe what the result SHOULD feel like.
   Concrete words like "sober" and "dense" give the AI a clear direction.

TRICK 2: USE PATTERN TEMPLATES FOR MULTIPLE PERSPECTIVES
   If you want the AI to show TWO things at the same time (like beauty AND
   critique), give it a PATTERN to follow:

   "In every detail, show SIMULTANEOUSLY:
   — [destruction/intervention] — and [life force/beauty in the same moment]
   — [human burden] — and [light/matter/nature responding to it]"

   The pattern forces the AI to produce BOTH sides in every sentence.
   It can't collapse into just one side because the template requires both.

TRICK 3: LIST EQUAL ELEMENTS
   Instead of one theme (like "ecology"), list MULTIPLE equal elements:
   — Material flows
   — Technical processes
   — Living organisms
   — Social connections
   — Power structures
   — Time layers

   Then say: "These elements are EQUAL. No element dominates."
   This distributes the AI's attention across all dimensions.

TRICK 4: KEEP EXAMPLES ABSTRACT
   If you include examples in your rules, make them ABSTRACT (about structure,
   not about specific topics):
   BAD:  "Example: A tractor plowing soil that was once forest"
         (Now every result will mention agriculture!)
   GOOD: "Pattern: [intervention] — and [living response]"
         (Teaches the SHAPE of what you want, not the TOPIC)

TRICK 5: AVOID TRIGGER WORDS
   Some words automatically push the AI into a specific mode:
   - "ecological" → produces environmental damage narratives
   - "critical" → produces suffering/exploitation narratives
   - "dystopia" (even negated!) → produces dystopian output

   Replace them with more specific, neutral descriptions of what you actually mean.

EXAMPLE: PLANETARIZER (BEFORE AND AFTER)
-----------------------------------------
BEFORE (collapsed):
   "Rewrite the input so it is entangled in its ecological connections.
   Goal is not dystopia, but situated realism."
   → Result: Every input became an environmental guilt lecture.

AFTER (fixed):
   "Describe the input as an ASSEMBLAGE — a configuration of heterogeneous
   elements that interact without obeying a single principle:
   — Material flows, Technical mediations, Living agents,
   — Social bonds, Hegemonic dispositifs, Temporal layers.
   These elements are EQUAL. Describe soberly, densely, concretely.
   No judgment. No accusation. Only description."
   → Result: Rich, multi-dimensional descriptions without guilt narratives.
