### 4.2 F12 fix is incomplete and should be reverted (USER'S DECISION)

Commit `24b2ef46` ("fix(config): unify _AI_TOOLS_BASE default + remove
hardcoded MODEL_DIR") is on GitHub but is wrong: it patches
`devserver/config.py` and `gpu_service/services/llm_backend.py` but
**does not** audit `install_systemd_services.sh`, which still uses the
OLD pre-F12 semantic (`AI_TOOLS_BASE=$(dirname "$SCRIPT_DIR")` =
`<home>` instead of `<home>/ai`).

Consequence after running `install_systemd_services.sh`: the systemd
units force `AI_TOOLS_BASE=<home>`, the F12 fix is silently
overridden, and `MODEL_DIR` resolves to `<home>/llama-server-models`
(wrong). Llama-Guard returns None, VLM safety blocks, Stage 3
fail-closes.

**Required approach:** The F12 fix caused follow-on errors. It is
reverted, and a correct fix for F12 is implemented in its place.

**Required workflow:**
1. Read-only research: grep every reference to `AI_TOOLS_BASE`,
   `_AI_TOOLS_BASE`, `MODEL_DIR`, `_SERVER_BASE`,
   `HEARTMULA_MODEL_PATH`, in code, scripts, and systemd unit templates.
   Make the dependency map.
2. Diagnose original F12 with full sight — including
   `install_systemd_services.sh`, the active systemd unit files at
   `/etc/systemd/system/ai4artsed-*.service`, and any other entry
   points (`5_start_backend_prod.sh` exports its own `AI_TOOLS_BASE`).
3. Propose a redesign — text only, no code.
4. After user OK on design: `git revert 24b2ef46` locally, implement
   the proper fix, show full diff, get second OK, then push.
5. After push: re-run `install_systemd_services.sh` and verify
   model-load paths resolve correctly.

different model (Qwen3-VL-Embedding-2B in embedding mode, not our
